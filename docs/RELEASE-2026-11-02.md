# MicroLedger — Paper & Peach update

Published source update prepared on 2 November 2026.

## Included changes

- Paper & Peach mobile interface, date-grouped Activity, search and category filters, centered expense button and goal views.
- First-run setup for name, companion, spending budget, category limits and an optional unfunded savings goal. Existing records remain intact; setup can be revisited from Profile.
- Sprout, cat and cloud companions with color, accessory, name and visibility settings. Animated blinking, winking, celebration, thinking and concerned expressions; reduced-motion preferences are respected.
- Profile appearance modes, custom categories shared across entry/planning/Insights, and persistent preferences.
- Expense, bill and goal deletion with a closable five-second undo notice. Clear-all expenses requires confirmation. Bill deletion keeps past payments; goal undo restores contributions.
- Type runs locally without an AI key. Switching from Scan clears the old receipt and receipt date context.
- Scan reads actual receipt pixels through local English Tesseract OCR. It validates labelled totals, rejects unclear/conflicting/foreign-currency results and requires review before saving.
- Receipt upload normalization, size/type errors, scan timeouts and protection against changing the receipt while extraction is running.

## Verification

- 53 automated regression tests pass, including actual-image OCR, PKR/date validation, setup, companion customization, backups, failed writes and deletion deadlines.
- `npm run lint` and `npm run build` pass.
- Local production-build browser checks cover an uploaded receipt, food and grocery receipt samples, Scan-to-Type switching, setup persistence, mascot expressions, phone layout and reduced-motion controls.

## Deployment and rollback

Install with `npm ci`, build, then run the Express server in production mode. No AI API key is required. Receipt recognition supports clear English printed receipts; users must check the review form. GitHub stores source and does not by itself host the Node OCR API.

Before rollback, download a full backup from Profile. Revert the release commit through a new commit so later work is preserved. Older builds may not understand custom categories or newer optional fields; keep the backup and active snapshot until returning to a compatible version. After rollback, verify saving, backups and the entry flows before reopening the app to users.
